gitvfs is a small family of packages for apps that keep their data in a Git repository and talk to
it straight from the browser, through the GitHub or GitLab API. There is no server to run and no
database to keep in sync: the repository is the source of truth, and every change is a commit.

## The packages

| Package | What it does |
| --- | --- |
| `gitvfs` | `GitFS`: `readFile`, `readdir`, `writeFile`, `rm`, `rename`, `commit`, with GitHub and GitLab providers and pluggable caching. |
| `gitvfs-cms` | Content types described with zod (`defineCollection`, `defineSingleton`) and a `GitCms` that reads, validates and commits them. |
| `gitvfs-cms/react` | `CmsApp`, a complete editor UI built with [AutoForm](https://autoform.vantezzen.io/), plus the pieces to build your own. |
| `gitvfs-cms/oidc` | A token provider backed by [oidc-spa](https://www.oidc-spa.dev/), so users sign in instead of pasting tokens. |

## These docs edit themselves

This site is a [Fumadocs](https://fumadocs.dev) app whose pages are MDX files in the gitvfs
repository. The [editor](/admin) is `gitvfs-cms` configured with one collection per docs folder:
sign in with a GitHub token and every save becomes a commit, which in turn redeploys the site.
