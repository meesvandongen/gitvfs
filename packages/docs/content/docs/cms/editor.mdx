## Fields

Forms are generated from the schema by AutoForm. Types are inferred from zod, and can be refined
with helpers that attach editor metadata through `.check()`:

| Schema | Field |
| --- | --- |
| `z.string()` | text input |
| `z.string().check(textarea())` | multi-line text |
| `z.string().check(markdown())` | markdown editor with toolbar and live preview |
| `z.number()` | number input |
| `z.boolean()` | checkbox |
| `z.coerce.date()` | date picker |
| `z.enum([...])` | select |
| `z.array(...)` | repeatable list |
| `z.object({...})` | group of fields |
| `z.array(z.object({...})).check(table())` | spreadsheet-like table, see [Table fields](#table-fields) |
| `tree({ fields })` | nested list edited as an outline, see [Tree fields](#tree-fields) |

`field({ label, description, order, inputProps, fieldType })` sets the other options:

```ts
title: z.string().min(1).check(field({ label: 'Title', description: 'Shown in the browser tab' })),
```

Optional groups (`z.object({...}).optional()`) that the user leaves blank are saved as absent, so
their required parts only apply once something is filled in.

Use `.default('')` on optional text such as the body: AutoForm treats empty inputs as missing, so a
plain required string rejects an empty body.

## Map fields

Five helpers return ready-made schemas edited on a map. Values are plain `{ lat, lng }` objects in
WGS 84 degrees, which read well in frontmatter, JSON and YAML (and avoid GeoJSON's
`[longitude, latitude]` order):

| Schema | Stored as | Editor |
| --- | --- | --- |
| `geoPoint()` | `{ lat, lng }` | click to place, drag the marker |
| `geoCircle()` | `{ lat, lng, radius }`, radius in meters | a point with a range: drag the edge handle or use the slider |
| `geoLine()` | `[{ lat, lng }, ...]` | click to add points, for routes |
| `geoPolygon()` | `[{ lat, lng }, ...]` | click to add corners, for areas; shows the area |
| `geoPoints()` | `[{ lat, lng }, ...]`, or `[{ lat, lng, label? }, ...]` with `labels: true` | several numbered markers, such as branches or stops |

```ts
import { geoCircle, geoPoint, geoPoints, geoPolygon } from 'gitvfs-cms'

const shops = defineCollection({
  name: 'shops',
  folder: 'data/shops',
  format: 'yaml',
  schema: z.object({
    title: z.string(),
    location: geoPoint({ label: 'Location', center: { lat: 52.37, lng: 4.9 }, zoom: 11 }),
    delivery: geoCircle({ label: 'Delivery range', minRadius: 250, maxRadius: 15_000 }).optional(),
    area: geoPolygon({ label: 'Service area', maxPoints: 50 }).optional(),
    branches: geoPoints({ label: 'Branches', labels: true }).optional(),
  }),
})
```

```yaml
location:
  lat: 52.374
  lng: 4.8897
delivery:
  lat: 52.374
  lng: 4.8897
  radius: 3000
branches:
  - lat: 52.3791
    lng: 4.9003
    label: Central Station
  - lat: 52.3579
    lng: 4.8813
```

Every map field also has latitude and longitude inputs that accept a pasted pair such as
`52.3731, 4.8922` (the format Google Maps copies), a **Use my location** button, and keyboard
controls (arrow keys pan, `+` and `-` zoom). Scrolling over the map scrolls the form; hold Ctrl or
⌘ to zoom with the wheel.

| Option | Default | |
| --- | --- | --- |
| `center`, `zoom` | `{ lat: 20, lng: 0 }`, `2` | Where an empty field opens. |
| `pointZoom` | `15` | Zoom used to show a single point. |
| `decimals` | `6` | Precision of picked coordinates (about 10 cm). |
| `height` | `320` | Map height in pixels. |
| `tiles` | `OSM_TILES` | Tile layer: `{ url, attribution, attributionUrl?, maxZoom?, subdomains? }`. |
| `defaultRadius`, `minRadius`, `maxRadius` | `1000`, `0`, none | `geoCircle` only; `maxRadius` adds a slider. |
| `minPoints`, `maxPoints` | `2`, `3` or `1`, none | `geoLine`, `geoPolygon` and `geoPoints`. |
| `labels` | `false` | `geoPoints` only: a label input per marker; blank labels are left out of the file. |
| `geocoder` | none | Address search above the map, see below. |

Lists (`geoLine`, `geoPolygon`, `geoPoints`) that are cleared are saved as absent, so make them
`.optional()` when they may be empty. **Show all** fits the map to every point of the list.

The map is built in, without a map library. Tiles come from OpenStreetMap by default; for heavy
use, read their [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) and point
`tiles` at another provider, per field or for all of them with `mapDefaults` (below):

```ts
const tiles = { url: 'https://tiles.example.com/{z}/{x}/{y}.png', attribution: '© Example' }
```

### Address search

Set `geocoder` to show a search box above the map. Search runs when the user presses Enter or the
**Search** button, and the results open in a list (arrow keys and Enter, or the mouse). Choosing one
moves the map to it (to its whole extent, such as a city, when the service reports one) and, for
`geoPoint` and `geoCircle`, sets the value; `geoPoints` adds a marker without a label; `geoLine` and
`geoPolygon` only move the map. Stored values stay plain coordinates: the address is not saved.

`nominatimGeocoder()` searches OpenStreetMap's [Nominatim](https://nominatim.org):

```ts
import { nominatimGeocoder } from 'gitvfs-cms'

const geocoder = nominatimGeocoder({ email: 'webmaster@example.com', countryCodes: ['nl', 'be'], language: 'nl' })
```

| Option | Default | |
| --- | --- | --- |
| `endpoint` | `https://nominatim.openstreetmap.org/search` | Your own instance or a compatible service. |
| `email` | none | Contact address sent with requests, so the operator can reach you. |
| `countryCodes` | all | Only places in these countries. |
| `language` | the browser's | Language of the result labels. |
| `limit` | `5` | Number of results. |
| `interval` | `1000` | Minimum milliseconds between requests to `endpoint`, across all fields. |
| `cacheSize` | `100` | Searches remembered, so repeating one sends no request. |

The public instance is free to use within its
[usage policy](https://operations.osmfoundation.org/policies/nominatim/), which applies to your
whole app: at most one request per second, an identified application, no search as you type,
cached results and visible attribution, and no bulk or systematic queries. The geocoder spaces
requests one second apart per endpoint, caches results, sends your site's origin as `Referer`
(and `email` when set), and the editor shows the OpenStreetMap credit under the results and never
searches while typing. For more than an occasional editor, run your own Nominatim or use a
commercial service.

Any other service fits behind the `Geocoder` type: an async function of the query and
`{ signal, near }` (an `AbortSignal`, and the map's center once it is zoomed in on a region) that
returns `{ label, lat, lng, bounds? }[]`, with `bounds` as `{ south, west, north, east }`. Pass
`signal` on to `fetch`, as a newer search aborts the previous one. Set `geocoder.attribution` to
show a credit under the results.

### Options for every map field

Instead of repeating `tiles` or `geocoder` per field, give them to `CmsApp` once. A field's own
options win:

```tsx
<CmsApp cms={cms} mapDefaults={{ tiles, geocoder: nominatimGeocoder({ email: 'webmaster@example.com' }) }} />
```

When you assemble your own editor, wrap it in `<MapDefaultsProvider value={{ tiles, geocoder }}>`
instead.

For your site, `toGeoJSON(value)` converts a value to a GeoJSON geometry (a circle becomes its center,
or a ring of points with `{ polygon: true }`; `geoPoints` markers become a MultiPoint with
`{ multiPoint: true }`), and `distance`, `pathLength` and `polygonArea` measure
in meters.

## Table fields

`table()` edits a list of objects as a spreadsheet-like grid instead of a stack of groups. It is a
check on an ordinary `z.array(z.object({...}))`, so the stored value is the same list of objects the
default list editor writes, and adding or removing `table()` never changes a file.

```ts
import { field, table } from 'gitvfs-cms'

plans: z
  .array(
    z.object({
      name: z.string().min(1).check(field({ label: 'Plan' })),
      tier: z.enum(['starter', 'team', 'enterprise']),
      monthly: z.number().min(0).check(field({ label: 'Per month' })),
      highlighted: z.boolean().default(false),
      availableFrom: z.coerce.date().optional(),
      features: z.array(z.string()).default([]),
    }),
  )
  .min(1)
  .check(table({ label: 'Plans' })),
```

```yaml
plans:
  - name: Team
    tier: team
    monthly: 12
    highlighted: true
    features:
      - Preview deployments
```

- One column per key, in schema order (or `field({ order })`), headed by its `field()` label.
  Strings, numbers, booleans, dates and enums are edited in the cell. Other columns (objects,
  lists, `markdown()`, custom field types) are shown read-only and their values are kept; give them
  a `.default()` or make them optional so new rows validate.
- **Keyboard:** arrow keys move between cells (left and right from the edge of the text; selects
  and date inputs keep their own arrow keys), Enter moves down and adds a row from the last one,
  Shift+Enter moves up, Tab moves on as usual, Alt+↑ and Alt+↓ move the row.
- **Paste** cells copied from a spreadsheet (tab-separated) or CSV text: the block lands at the
  focused cell, overwriting cells and adding rows past the end. When its first line names the
  columns (by key or label) it is used as a header and columns are matched by name. Numbers,
  booleans (`yes`, `x`, `1`, …), enum labels and dates are converted; text that does not fit is
  kept so validation points at it.
- **Copy as CSV** copies the rows with a header of column keys; **Copy for spreadsheets** copies
  tab-separated text, which spreadsheets split into cells.
- Errors appear in the cell they belong to (`plans.2.monthly`). Wide tables scroll sideways.

The CSV helpers are exported for your own imports and exports: `parseDelimited(text, delimiter?)`
(RFC 4180 quotes, detects tab, semicolon or comma), `serializeDelimited(rows, delimiter?)`,
`rowsToCsv(rows, columns)` and `pasteCells(...)`.

## Tree fields

`tree()` returns a schema for nested lists such as navigation menus and page hierarchies, edited as
an outline. Each node has your fields and, when it has any, a `children` list of nodes. Leaves have
no `children` key: empty child lists are dropped when saving, so files stay short and adding a
level does not touch the siblings.

```ts
import { field, tree } from 'gitvfs-cms'

const navigation = defineSingleton({
  name: 'navigation',
  path: 'data/navigation.yml',
  schema: z.object({
    main: tree({
      label: 'Main menu',
      maxDepth: 3,
      fields: {
        label: z.string().min(1),
        href: z.string().min(1).optional().check(field({ label: 'Link' })),
        external: z.boolean().optional(),
      },
    }).default([]),
  }),
})
```

```yaml
main:
  - label: Home
    href: /
  - label: Docs
    href: /docs
    children:
      - label: Getting started
        href: /docs/getting-started
```

| Option | Default | |
| --- | --- | --- |
| `fields` | | The zod shape of every node. |
| `childrenKey` | `'children'` | Key of the child list, such as `'pages'`. |
| `maxDepth` | unlimited | Most levels; deeper nodes fail validation and the editor will not create them. |
| `labelField` | `label`, `title` or `name` | Field shown as the item's title in the outline. |
| `label`, `description`, … | | As for `field()`. |

The editor follows the [ARIA tree pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/):
arrow keys move between items and expand or collapse them, Home and End jump, Enter (or the
**Edit** button) opens an item's fields inline, Enter or Escape closes them, Alt+↑ and Alt+↓ move an
item among its siblings, Alt+→ indents it under the item above and Alt+← moves it out of its parent,
and Delete removes it (asking first when it has nested items). The selected item has buttons for the
same actions, plus **Add item after** and **Add child**. Rows can be dragged: the top or bottom
edge of a row places the item before or after it, the middle nests it inside. Items with errors are
marked and listed below the tree, with a link that opens them.

The children are a `z.lazy()` schema, because AutoForm walks object shapes eagerly and would
recurse forever into a zod 4 getter. The values type as `TreeNode<...>`, and `z.toJSONSchema`
produces a recursive `$ref`. For your site, `flattenTree(nodes)` lists nodes with their depth, and
`moveNode`, `indentNode`, `outdentNode`, `insertNode`, `removeNode` and `remapPath` are the pure
helpers the editor uses.

## Preview

The editor shows two tabs next to the form:

- **Preview** renders the title and markdown body. Content is rendered in an `iframe` that is
  sandboxed without scripts and with a strict content security policy, so content from the
  repository can never run code next to the user's token. Pass `previewStylesheets` to style it
  like your site.
- **Source** shows the exact file the next save will commit.

Replace the rendered preview per collection:

```tsx
<CmsApp cms={cms} previews={{ posts: ({ values }) => <PostCard post={values} /> }} />
```

## Choosing a repository

When users sign in, let them pick the repository to edit instead of fixing it in code.
`RepositoryPicker` lists what the provider returns, with a search box, and hands back the choice:

```tsx
import { RepositoryPicker } from 'gitvfs-cms/react'

function Admin({ gh }: { gh: GitProvider }) {
  const [cms, setCms] = useState<GitCms>()
  if (!cms) {
    return (
      <RepositoryPicker
        provider={gh}
        onSelect={(repo) =>
          setCms(createCms({
            fs: new GitVFS({ repository: gh.repository(repo.fullName), branch: repo.defaultBranch ?? 'main' }),
            collections: [posts],
          }))
        }
      />
    )
  }
  return <CmsApp cms={cms} />
}
```

Pass `filter` to offer only some repositories, for example those under your organization, and
`onCancel` to show a Cancel button when users switch from a repository they already have open.
The [CMS demo](https://demo.cms.gitvfs.mvd.im) does this with **Switch repository**.

## Building your own UI

`CmsApp` is assembled from exported parts, so you can embed only what you need:

- `CmsProvider` and `useCms()` share a `GitCms` instance.
- `DocumentEditor` loads, edits, previews and commits one entry or singleton.
- `ContentForm` is the AutoForm for a content type, with the CMS field components.
- `DocumentPreview`, `MarkdownPreview` and `PreviewFrame` render previews.
- `uiComponents` and `formComponents` are the AutoForm components; override any of them through
  the `uiComponents` and `formComponents` props, for example to add a custom `fieldType`.

## Styling

Import `gitvfs-cms/styles.css`. All classes are prefixed with `gcms-`, and colors, radius and fonts
are custom properties on `.gcms-app` (`--gcms-accent`, `--gcms-bg`, …). Dark mode follows
`prefers-color-scheme`.
