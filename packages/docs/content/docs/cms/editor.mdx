## Fields

Forms are generated from the schema by AutoForm. Types are inferred from zod, and can be refined
with helpers that attach editor metadata through `.check()`:

| Schema | Field |
| --- | --- |
| `z.string()` | text input |
| `z.string().check(textarea())` | multi-line text |
| `z.string().check(markdown())` | markdown editor with toolbar and live preview |
| `z.number()` | number input |
| `z.boolean()` | checkbox |
| `z.coerce.date()` | date picker |
| `z.enum([...])` | select |
| `z.array(...)` | repeatable list |
| `z.object({...})` | group of fields |

`field({ label, description, order, inputProps, fieldType })` sets the other options:

```ts
title: z.string().min(1).check(field({ label: 'Title', description: 'Shown in the browser tab' })),
```

Optional groups (`z.object({...}).optional()`) that the user leaves blank are saved as absent, so
their required parts only apply once something is filled in.

Use `.default('')` on optional text such as the body: AutoForm treats empty inputs as missing, so a
plain required string rejects an empty body.

## Map fields

Four helpers return ready-made schemas edited on a map. Values are plain `{ lat, lng }` objects in
WGS 84 degrees, which read well in frontmatter, JSON and YAML (and avoid GeoJSON's
`[longitude, latitude]` order):

| Schema | Stored as | Editor |
| --- | --- | --- |
| `geoPoint()` | `{ lat, lng }` | click to place, drag the marker |
| `geoCircle()` | `{ lat, lng, radius }`, radius in meters | a point with a range: drag the edge handle or use the slider |
| `geoLine()` | `[{ lat, lng }, ...]` | click to add points, for routes |
| `geoPolygon()` | `[{ lat, lng }, ...]` | click to add corners, for areas; shows the area |

```ts
import { geoCircle, geoPoint, geoPolygon } from 'gitvfs-cms'

const shops = defineCollection({
  name: 'shops',
  folder: 'data/shops',
  format: 'yaml',
  schema: z.object({
    title: z.string(),
    location: geoPoint({ label: 'Location', center: { lat: 52.37, lng: 4.9 }, zoom: 11 }),
    delivery: geoCircle({ label: 'Delivery range', minRadius: 250, maxRadius: 15_000 }).optional(),
    area: geoPolygon({ label: 'Service area', maxPoints: 50 }).optional(),
  }),
})
```

```yaml
location:
  lat: 52.374
  lng: 4.8897
delivery:
  lat: 52.374
  lng: 4.8897
  radius: 3000
```

Every map field also has latitude and longitude inputs that accept a pasted pair such as
`52.3731, 4.8922` (the format Google Maps copies), a **Use my location** button, and keyboard
controls (arrow keys pan, `+` and `-` zoom). Scrolling over the map scrolls the form; hold Ctrl or
⌘ to zoom with the wheel.

| Option | Default | |
| --- | --- | --- |
| `center`, `zoom` | `{ lat: 20, lng: 0 }`, `2` | Where an empty field opens. |
| `pointZoom` | `15` | Zoom used to show a single point. |
| `decimals` | `6` | Precision of picked coordinates (about 10 cm). |
| `height` | `320` | Map height in pixels. |
| `tiles` | `OSM_TILES` | Tile layer: `{ url, attribution, attributionUrl?, maxZoom?, subdomains? }`. |
| `defaultRadius`, `minRadius`, `maxRadius` | `1000`, `0`, none | `geoCircle` only; `maxRadius` adds a slider. |
| `minPoints`, `maxPoints` | `2` or `3`, none | `geoLine` and `geoPolygon`. |

The map is built in, without a map library. Tiles come from OpenStreetMap by default; for heavy
use, read their [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) and point
`tiles` at another provider, for example with your own helper:

```ts
const tiles = { url: 'https://tiles.example.com/{z}/{x}/{y}.png', attribution: '© Example' }
const place = (config = {}) => geoPoint({ tiles, ...config })
```

For your site, `toGeoJSON(value)` converts a value to a GeoJSON geometry (a circle becomes its center,
or a ring of points with `{ polygon: true }`), and `distance`, `pathLength` and `polygonArea` measure
in meters.

## Media fields

Images and other files are uploaded into the repository, next to the content, like Decap CMS's
`media_folder` and `public_folder` or Keystatic's `fields.image({ directory, publicPath })`. Each
field names a repository `folder` and the `publicPath` your site serves it at; content stores the
public URL, so templates use it as is.

| Schema | Stored as | Editor |
| --- | --- | --- |
| `image()` | `{ src, alt?, focus? }` | drop or browse, pick an existing image, preview with file size and dimensions, alt text, focal point |
| `imagePath()` | `'/images/team.jpg'` | the same, without alt text and focal point, for templates that expect a plain path |
| `gallery()` | `[{ src, alt?, focus? }, ...]` | several images at once; reorder by dragging or with the arrow buttons |
| `file()` | `'/files/menu.pdf'` | any file type, with name, size and a download button |
| `embed()` | `'https://youtu.be/…'` | a link; YouTube and Vimeo get a player that loads only on request |
| `markdown({ media })` | `![alt](/images/x.png)` in the body | an **Image** button in the toolbar that uploads or picks an image and inserts it at the cursor |

```ts
import { embed, file, gallery, image, markdown } from 'gitvfs-cms'

const images = { folder: 'public/images/posts', publicPath: '/images/posts', maxSize: 2 * 1024 * 1024 }

const posts = defineCollection({
  name: 'posts',
  folder: 'content/posts',
  schema: z.object({
    title: z.string(),
    cover: image({ label: 'Cover', ...images }).optional(),
    photos: gallery({ label: 'Photos', ...images, max: 12 }).optional(),
    menu: file({ label: 'Menu', folder: 'public/files', accept: '.pdf' }).optional(),
    video: embed({ label: 'Video', providers: ['youtube', 'vimeo'] }).optional(),
    body: z.string().check(markdown({ media: images })).default(''),
  }),
})
```

```yaml
cover:
  src: /images/posts/team.jpg
  alt: The team on the roof terrace
  focus:
    x: 0.5
    y: 0.3
photos:
  - src: /images/posts/talk.jpg
    alt: A talk in the main hall
menu: /files/menu.pdf
video: https://www.youtube.com/watch?v=aircAruvnKk
```

**Saving.** Uploads wait in the editor until the document is saved, then go into the same commit as
the document: one commit per save, as everywhere in the CMS. Only uploads the saved values still
refer to are committed, so an image that was replaced or removed before saving never reaches the
repository. File names are made safe (`Team Photo.JPG` becomes `team-photo.jpg`) and get `-2`, `-3`,
... when the name is taken; uploads never overwrite a file. When a save fails, nothing stays staged.
Without the React editor, pass the files yourself:

```ts
await cms.saveEntry('posts', {
  slug: 'hello',
  data: { title: 'Hello', cover: { src: '/images/posts/team.jpg', alt: 'The team' } },
  assets: [{ path: 'public/images/posts/team.jpg', content: bytes }],
})
const path = await cms.availableAssetPath('public/images/posts', 'Team.JPG') // a free path
```

**Showing files.** The editor reads stored files through the CMS, so they show for private
repositories too, and caches them per CMS. `toRepoPath(media, src)` and `toPublicPath(media, path)`
map between the two. Custom previews can call `useMediaUrl(src)` from `gitvfs-cms/react` to show a
stored or just uploaded image.

The markdown **Preview** frame is sandboxed into an opaque origin that cannot load the editor's
`blob:` URLs, so images under a media folder are inlined as `data:` URLs before the HTML goes into
the frame. Its content security policy already allowed `data:` images, so nothing was loosened:
the frame still runs no scripts. The cost is that large images make the preview document bigger;
other image URLs are left alone and load as before (resolved against `previewBaseUrl`).

**Focal point.** Click the image (or use the arrow keys) to set the point that crops keep in view,
stored as fractions from the top left. On the site, `focusToObjectPosition(image.focus)` gives the
CSS `object-position` (`'50% 30%'`), and works for `background-position` too.

**Embeds.** `parseEmbedUrl(url)` returns `{ provider, id, embedUrl, start }` for YouTube (watch,
`youtu.be`, shorts, live and embed links) and Vimeo (including unlisted links), and `{ provider: 'url' }`
for other http(s) links. The editor loads nothing from those sites until **Load preview** is
clicked, and then uses `youtube-nocookie.com` or Vimeo's do-not-track flag. Use `embedUrl` on your
site the same way.

| Option | Default | |
| --- | --- | --- |
| `folder` | `public/images` (`file()`: `public/files`) | Repository folder uploads are committed to. |
| `publicPath` | `folder` from the root, without `public/` or `static/` | URL stored in content, e.g. `/images`. Can be a full URL for a CDN. |
| `accept` | `image/*` (`file()`: any) | Accepted types, as in `<input accept>`: `image/*,.pdf`. |
| `maxSize` | 10 MB | Largest upload in bytes. Git hosts are not made for large binaries; keep it small. |
| `requireAlt` | `false` | `image()` and `gallery()`: make alt text required. |
| `focalPoint` | `true` | `image()` and `gallery()`: offer the focal point picker. |
| `min`, `max` | none | `gallery()`: number of images. |
| `providers` | all | `embed()`: `['youtube', 'vimeo', 'url']`, or a subset. |

`image()` keeps keys it does not know, such as a `caption` added by hand. Uploaded SVG files can
contain scripts that run when the file is opened directly on your site; use `accept` to leave out
`image/svg+xml` if editors are not fully trusted.

## Preview

The editor shows two tabs next to the form:

- **Preview** renders the title and markdown body. Content is rendered in an `iframe` that is
  sandboxed without scripts and with a strict content security policy, so content from the
  repository can never run code next to the user's token. Pass `previewStylesheets` to style it
  like your site.
- **Source** shows the exact file the next save will commit.

Replace the rendered preview per collection:

```tsx
<CmsApp cms={cms} previews={{ posts: ({ values }) => <PostCard post={values} /> }} />
```

## Choosing a repository

When users sign in, let them pick the repository to edit instead of fixing it in code.
`RepositoryPicker` lists what the provider returns, with a search box, and hands back the choice:

```tsx
import { RepositoryPicker } from 'gitvfs-cms/react'

function Admin({ gh }: { gh: GitProvider }) {
  const [cms, setCms] = useState<GitCms>()
  if (!cms) {
    return (
      <RepositoryPicker
        provider={gh}
        onSelect={(repo) =>
          setCms(createCms({
            fs: new GitVFS({ repository: gh.repository(repo.fullName), branch: repo.defaultBranch ?? 'main' }),
            collections: [posts],
          }))
        }
      />
    )
  }
  return <CmsApp cms={cms} />
}
```

Pass `filter` to offer only some repositories, for example those under your organization, and
`onCancel` to show a Cancel button when users switch from a repository they already have open.
The [CMS demo](https://demo.cms.gitvfs.mvd.im) does this with **Switch repository**.

## Building your own UI

`CmsApp` is assembled from exported parts, so you can embed only what you need:

- `CmsProvider` and `useCms()` share a `GitCms` instance.
- `DocumentEditor` loads, edits, previews and commits one entry or singleton.
- `ContentForm` is the AutoForm for a content type, with the CMS field components.
- `DocumentPreview`, `MarkdownPreview` and `PreviewFrame` render previews.
- `MediaStore` and `MediaProvider` hold the uploads of media fields until a save. `DocumentEditor`
  provides them; with a `ContentForm` of your own, wrap it in a `MediaProvider`, pass
  `await store.assets(values)` as the save's `assets`, then call `store.committed(paths)`.
- `uiComponents` and `formComponents` are the AutoForm components; override any of them through
  the `uiComponents` and `formComponents` props, for example to add a custom `fieldType`.

## Styling

Import `gitvfs-cms/styles.css`. All classes are prefixed with `gcms-`, and colors, radius and fonts
are custom properties on `.gcms-app` (`--gcms-accent`, `--gcms-bg`, …). Dark mode follows
`prefers-color-scheme`.
