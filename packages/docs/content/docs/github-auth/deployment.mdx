These docs show the setup: one Worker serves the prerendered site as static assets and runs code
only for `/api/github/*`.

## The Worker

```ts title="worker/index.ts"
import { createTokenHandler, originMatcher } from 'gitvfs-github-auth/server'

interface Env {
  GITHUB_CLIENT_ID?: string
  GITHUB_CLIENT_SECRET?: string
  GITHUB_SCOPE?: string
  GITHUB_ALLOWED_ORIGINS?: string
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url)
    // Comma-separated, with patterns such as https://*.docs.example.com for previews.
    const origins = (env.GITHUB_ALLOWED_ORIGINS ?? '').split(',')
    const enabled = Boolean(env.GITHUB_CLIENT_ID && env.GITHUB_CLIENT_SECRET) && originMatcher(origins)(url.origin)

    if (url.pathname === '/api/github/config') {
      return Response.json(enabled ? { clientId: env.GITHUB_CLIENT_ID, scope: env.GITHUB_SCOPE } : { clientId: null })
    }
    if (url.pathname === '/api/github/token' && enabled) {
      return createTokenHandler({
        clientId: env.GITHUB_CLIENT_ID!,
        clientSecret: env.GITHUB_CLIENT_SECRET!,
        allowedOrigins: origins,
      })(request)
    }
    return Response.json({ error: 'not_found' }, { status: 404 })
  },
}
```

`/api/github/config` lets the page find out whether sign-in is available on the current origin.
The editor shows **Sign in with GitHub** only when it is, and falls back to personal access tokens
elsewhere.

## Configuration

```jsonc title="wrangler.jsonc"
{
  "name": "gitvfs",
  "main": "./worker/index.ts",
  "vars": {
    "GITHUB_CLIENT_ID": "Iv23li…",
    // OAuth Apps only; GitHub Apps ignore it.
    "GITHUB_SCOPE": "public_repo",
    "GITHUB_ALLOWED_ORIGINS": "https://docs.example.com",
  },
  "assets": {
    "directory": "./build/client",
    // Only the token routes run the Worker; everything else is served as a static file.
    "run_worker_first": ["/api/github/*"],
  },
  // Previews do not inherit production settings.
  "previews": {
    "vars": {
      "GITHUB_CLIENT_ID": "Iv23li…",
      "GITHUB_ALLOWED_ORIGINS": "https://*.docs.example.com",
    },
  },
}
```

Set the secret once per Worker:

```sh
pnpm exec wrangler secret put GITHUB_CLIENT_SECRET
```

Deploy the Worker script first. Cloudflare refuses variables and secrets on a Worker that only has
static assets ("Variables cannot be added to a Worker that only has static assets"), so when you
add the Worker to an existing assets-only site, the first deployment with `main` has to happen
before the secret can be set. Until the secret exists, sign-in simply stays off.

Variables at the top level apply to production only; [Worker
Previews](https://developers.cloudflare.com/workers/previews/) get theirs from the `previews` block.
Preview URLs are subdomains of the production domain (`<branch>.docs.example.com`), so they sign in
with the same app once its callback URL has **wildcard matching** enabled. The secret is set
separately, once, in the base config that all previews share:

```sh
pnpm exec wrangler preview base-config secret put GITHUB_CLIENT_SECRET
```

Without it, previews offer token sign-in only.

## Local development

Put the secret in `.dev.vars` (keep it out of Git), then run the built site on the Workers runtime
with sign-in enabled for the local origin:

```sh
printf 'GITHUB_CLIENT_SECRET=…\n' > .dev.vars
pnpm run build
pnpm exec wrangler dev --var GITHUB_CLIENT_ID:Iv23li… --var GITHUB_ALLOWED_ORIGINS:http://localhost:8787
```

Add `http://localhost:8787/admin` as a callback URL of the app for this to work.
