`gitvfs` is a filesystem-style wrapper over Git provider APIs. It lets apps browse repositories,
stage edits locally, and commit them back to GitHub or GitLab, without cloning anything.

## Install

```sh
pnpm add gitvfs
```

## Quick start

```ts
import { GitFS } from 'gitvfs'
import { github } from 'gitvfs/providers/github'

const fs = new GitFS({
  provider: github({
    owner: 'acme',
    repo: 'docs',
    token: () => localStorage.getItem('github_token') ?? '',
  }),
  branch: 'main',
})

const readme = await fs.readFile('README.md', { encoding: 'utf-8' })
fs.writeFile('notes/todo.txt', 'hello from gitvfs\n')
await fs.commit('Add todo file')
```

Reads go to the API (and the cache); writes are staged in memory until you call `commit`, which
creates a single commit with every staged change.

## Features

- GitHub and GitLab providers, including GitHub Enterprise and self-managed GitLab
- Filesystem-like reads: `readFile`, `readdir`, `exists`, `stat`
- Local staging for writes, deletes and renames, overlaid on reads
- Separate read and write branches, and optional auto-commit
- Text and binary files
- Memory, IndexedDB or custom caches, invalidated when the branch head changes
- Typed errors for authentication, rate limits, conflicts and missing files

Try it in the [demo](https://gitvfs-demo.mvd.im/), which browses and edits your own repositories
with a personal access token.
